# سامانهٔ متن‌باز ردیابی GPS

این مخزن هر سه بخش یک پروژه را کنار هم قرار می‌دهد: **فریمور ESP32-C3، اپلیکیشن اندروید و سرور GPS**. دستگاه موقعیت را با GPS دریافت می‌کند، از طریق SIM800 و MQTT به سرور می‌فرستد و اپ آن را روی نقشه نمایش می‌دهد. فرمان رله، احراز هویت پیامکی، محدودهٔ جغرافیایی و بازیابی نقاط ثبت‌شده هنگام قطعی شبکه نیز بخشی از همین سامانه‌اند.

## راهنمای بخش‌ها

| بخش | وظیفه | مستندات |
| --- | --- | --- |
| `firmware` | خواندن GPS، مودم SIM800، ارسال MQTT، رله، هشدار، بافر آفلاین، OTA | [راهنمای فریمور](firmware/README.md) |
| `android` | ورود، نقشه، داشبورد، تاریخچه، محدودهٔ جغرافیایی، تنظیمات، سرویس پس‌زمینه | [راهنمای اندروید](android/README.md) |
| `server` | API، پایگاه داده، دریافت MQTT، کاربران، دستگاه‌ها، سفرها، حصارها و داشبورد وب | [راهنمای سرور](server/README.md) |
| `docs` | تشریح ارتباط بخش‌ها، قرارداد پیام‌ها، فهرست فایل‌ها، محدودیت‌ها و نتیجهٔ بررسی‌ها | [معماری](docs/ARCHITECTURE.md) و [پیام‌های MQTT](docs/MQTT_PROTOCOL.md) |

## دستگاه چگونه کار می‌کند؟

`GPSManager` دادهٔ سریال GPS را با TinyGPSPlus می‌خواند. تعداد ماهواره، HDOP و سن موقعیت بررسی می‌شود؛ جهش نامعقول حذف و موقعیت پذیرفته‌شده هموار می‌شود. `SIM800Manager` شبکه، GPRS و پیامک را مدیریت می‌کند. `SIM800Client` ارتباط TCP را به رابط Arduino Client تبدیل می‌کند تا `MQTTManager` بتواند از PubSubClient استفاده کند.

حلقهٔ اصلی در `firmware/src/main.cpp` مدیرها، وضعیت شبکه، پیامک OTP، هشدار تماس، جیوفنس و همگام‌سازی را هماهنگ می‌کند. موقعیت زنده تقریباً هر سه ثانیه و heartbeat هر سی ثانیه ارسال می‌شود. نقاط backlog با دورهٔ جداگانهٔ پانزده ثانیه ذخیره می‌شوند؛ این بازه‌ها در `include/config.h` قابل تغییرند.

`LocationBuffer` نقاط را ابتدا در RAM و سپس در LittleFS نگه می‌دارد. بعد از وصل شدن شبکه، دستگاه `sync/hello` می‌فرستد و سرور شمارهٔ آخرین نقطهٔ شناخته‌شده را در `sync/ack` برمی‌گرداند. این سازوکار برای جبران قطعی طراحی شده، اما تضمین تراکنشی تحویل همهٔ نقاط ندارد؛ محدودیت دقیق در مستندات آمده است.

`OTAManager` برای دانلود مرحله‌ای با HTTP Range، کنترل SHA-256 و ذخیرهٔ وضعیت به‌روزرسانی نوشته شده است. هنگام OTA، عملیات عادی حلقه محدود می‌شود. سرویس انتشار فایل و API دریافت آخرین فریمور در بکاپ موجود نیست و باید جداگانه فراهم شود.

## اپ اندروید

اپ با Kotlin و ساختار Fragment/ViewModel پیاده شده است. صفحهٔ ورود با API سرور کار می‌کند. داشبورد با OSMDroid و نقشهٔ OpenStreetMap موقعیت و مسیر را نشان می‌دهد و وضعیت سرعت، شبکه و موتور را نمایش می‌دهد. تاریخچه از سرور خوانده می‌شود و بخش‌هایی از داده‌ها با Room روی گوشی ذخیره می‌شوند.

در جیوفنس، محدوده‌ها از API مدیریت و تنظیمات به دستگاه MQTT ارسال می‌شوند. `GpsForegroundService` اتصال MQTT و ارسال موقعیت خود گوشی را هم انجام می‌دهد. اگر گوشی و سخت‌افزار با یک شناسه کار کنند، ممکن است دو منبع روی یک تاپیک داده منتشر کنند؛ شناسه‌ها و کاربرد سرویس را پیش از استفاده مشخص کنید.

ظاهر Aurora با منابع XML و ویجت‌های سفارشی سرعت‌سنج، رادار پالسی، نقطهٔ وضعیت و نمودار زنده ساخته شده است. راهنمای اصلی اپ، نقش هر فایل و نیازمندی‌های بیلد را توضیح می‌دهد.

## سرور

FastAPI درخواست‌ها را دریافت می‌کند؛ SQLAlchemy و asyncpg با PostgreSQL کار می‌کنند. Paho MQTT پیام‌های دستگاه را می‌خواند و موقعیت، وضعیت رله و هشدارها را ذخیره می‌کند. API برای ورود با رمز یا OTP، ثبت دستگاه، آخرین موقعیت، تاریخچه، سفر، جیوفنس و مدیریت کاربران وجود دارد.

Nginx داشبورد HTML و API را در یک آدرس ارائه می‌دهد. Mosquitto بروکر MQTT است. Redis در Compose پیش‌بینی شده ولی وضعیت OTP در این نسخه داخل حافظهٔ فرایند نگه‌داری می‌شود؛ بنابراین فعلاً backend را با یک worker اجرا کنید.

نسخهٔ بکاپ دو مجموعهٔ کد سرور داشت. نسخهٔ روی دیسک چهار اصلاح جدیدتر دارد: محدود کردن جیوفنس به مالک دستگاه، انتشار هشدارهای ورود/خروج، و رفع خطای حذف حصار با مدیریت کلید خارجی. نسخهٔ اصلی مخزن از کد روی دیسک استفاده می‌کند و چهار فایل قدیمی در آرشیو حفظ شده‌اند.

## راه‌اندازی

سرور توسعه:

```sh
cd server
python scripts/init_config.py
docker compose up -d --build
docker compose exec backend python create_admin.py
```

داشبورد: `http://localhost:8081`؛ مستندات تعاملی API: `http://localhost:8081/docs`.

فریمور:

```sh
cd firmware
# local_config.example.h را به local_config.h کپی و تنظیم کنید.
pio run -e nologo_esp32c3_super_mini
pio run -e nologo_esp32c3_super_mini -t upload
```

اپ: پوشهٔ `android` را با Android Studio باز کنید؛ JDK 17 و SDK 34 لازم است. فایل `gps.properties.example` را به `gps.properties` کپی کنید و آدرس سرور و بروکر خود را تنظیم کنید. پیش‌فرض برای شبیه‌ساز اندروید است. خروجی debug با دستور `gradlew.bat :app:assembleDebug` ساخته می‌شود.

شناسهٔ دستگاه در فریمور و اپ باید یکسان باشد؛ برای نمونه `device_1`. تاپیک‌های فریمور از `DEVICE_ID` ساخته می‌شوند. تنظیمات خصوصی در فایل‌های محلی مستثنا از Git قرار می‌گیرند.

## انتشار عمومی و محدودیت‌ها

رمزها، کلید TLS، دیتای Mosquitto، لاگ‌ها، keystore، مسیرهای اختصاصی کامپیوتر و خروجی بیلد از مخزن عمومی حذف شده‌اند. فایل ZIP خام منتشر نمی‌شود؛ کد مفید آن استخراج شده است. تنظیمات نمونه، راهنمای اجرای مستقل و مجوز فونت‌های Inter و Vazirmatn افزوده شده‌اند. مجوز MIT شامل کد متعلق به پروژه است؛ وابستگی‌ها و فونت‌ها مجوز خودشان را دارند.

مخزن یک انتشار منبع قابل بررسی است. آزمون سخت‌افزار و شبکهٔ زنده با بررسی بیلد متفاوت است. پیش از نصب واقعی، [محدودیت‌های شناخته‌شده](docs/KNOWN_LIMITATIONS.md) و [گزارش بررسی](docs/VALIDATION.md) را بخوانید؛ مخصوصاً حفاظت تاپیک‌های MQTT، تنظیم OTP، منبع موقعیت، سیم‌بندی رله و اصالت فریمور OTA.
